# 04 同一个标识按用途分级：IP 的四分口径（含一处诚实修正）

> 本篇属于《敏感字段的暴露面最小化》系列第 04 段。前几段守"字段怎么不出现在响应里"，这段守"字段一开始该不该存、存了给谁看"。
> 时点护栏：取自 Inkglean 实现快照（2026-09-前），不表示当前仍如此

## 一个标识，四种用途，四套口径

"来源 IP"是一个物理标识，但在一个平台里它可能被出于**完全不同目的**采集。若把它们混成一个字段、一套可见性规则，一定会出错——要么为某个取证用途把 IP 到处存，顺带泄露；要么为隐私一律不存，纠纷时又拿不出证据。本案例的做法是**按用途拆成四类，各给各的口径**：

| 用途 | 存不存 | 谁能看 | 理由 |
|---|---|---|---|
| 交付下载取证 | 存 | 仅管理端（取证） | 只有"要证明某次下载/交付是谁干的"才需要留 IP |
| 登录留痕 | 存 | 仅管理端 | 账号安全排查用，画师本人在普通资料接口看不到 |
| 举报 / 留言的管理动作取证 | 存 | 仅管理端读路径 | 辱骂/侵权/威胁类留言要能查来源，但来源标识只到管理端为止 |
| 埋点 / 统计 | **绝不存 IP** | —— | 分析用途根本不需要可识别来源，改走随机匿名凭证 |

四条口径背后是同一条原则：**同一物理标识不等于同一逻辑字段；按用途最小化取用**（数据最小化的落地版）。埋点那行尤其关键——很多系统把 IP 当"分析维度"顺手存了一堆，那才是最大的无谓暴露面；正确做法是分析要匿名，就用随机匿名凭证（每次/每会话一个不含来源信息的 token），别拿 IP 凑。

## 为什么"举报/留言来源 IP"只到管理端为止

这不是技术洁癖，是业务后果。被举报相关方（比如收到恶意留言的画师）**不是执法者，也没有处置权**。把"这条留言来自某公网地址"直接摆进画师后台，可预见的后果是：画师自行去查 IP 归属地、在社交平台挂人——反而把平台拖进二次纠纷。所以来源标识只在管理端（权利人指定的执法入口）可读，画师端与公开端按第 01、02 段的"按构造"根本取不到这一列。

> 一句话：**"谁需要这条数据来完成他的职责"决定它能出现在哪些读路径**，而不是"这条数据顺手 join 出来了就给"。

## 存值的两条纪律

1. **取不到存 NULL，不写占位串**：来源取不到时存 `NULL`，绝不写 `"unknown"` / `"N/A"` 之类的占位字符串。占位串会在取证时被当成"一个真实值"参与统计或匹配，污染数据；`NULL` 才是"确实没有"的诚实表达。测试里专门有一条断言这个：落库值 `IS NULL` 且 `!= 'unknown'`。
2. **入库前做长度钳制**：来源标识写库前按 IPv6 最大文本长度（45 字符）截断，只为防超长请求头灌库，不是安全边界本身。

## 诚实修正：别把"统一常量"讲重

在描述本案例时，很容易顺口说一句"敏感字段都用统一常量管理"。这句话**只对了一半，必须收窄**：

- "安全列清单"确实被提成了**单一常量**、被多条非管理端读路径复用（第 02 段件一）——这部分"统一常量"成立；
- 但上面那条**长度钳制的上限值并非"一处定义、全局复用"**：实际是一处在写入侧定义并使用、另一处（例如校验/测试边界）各自把字面量写死。两处恰好取了同一个数值，但不存在"改一处全变"的单一事实源。

所以本篇的准确表述是：**"安全列清单"是统一常量；"长度钳制上限"是两处各写字面量、值碰巧一致，不是复用同一常量。** 把后者也讲成"统一常量"就是夸大。这类"某物被提取为常量 ≠ 所有相关阈值都被统一收口"的坑，写方法论时特别容易顺手美化，这里点名自纠。

## 本段要点回顾

- 同一标识按用途分级，各给"存不存 / 谁能看"的独立口径；埋点一律不存可识别来源；
- 可见性由"职责需要"决定，不是由"查询顺手 join 到了"决定；
- 取不到存 NULL 不写占位串；
- 诚实边界：只有安全列清单是统一常量，长度钳制上限是两处字面量巧合，别混为"统一常量"。
