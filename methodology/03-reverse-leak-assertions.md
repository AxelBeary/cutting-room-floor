# 03 逆泄露断言：把"敏感值不出现在响应体任意位置"钉进测试

> 本篇属于《敏感字段的暴露面最小化》系列第 03 段。承接第 02 段——三件套是"做对"，这段讲"怎么证明没做破"。
> 时点护栏：取自 Inkglean 实现快照（2026-09-前），不表示当前仍如此

## 什么叫"逆泄露断言"

常规接口测试是**正向**的：断言响应里该有的字段在、值对。
逆泄露断言是**反向**的：断言响应里**不该有的敏感字段，名字和值都不许出现**。

它守的是前面几层防线"被无意写破"的情形——比如哪天有人图省事把某条读路径改回 `SELECT *`，或在出口忘了裁剪。三件套是构造保证，逆泄露断言是**回归保证**：保证构造性保证不被后来的提交悄悄拆除。

## 三类断言，覆盖面逐级加码

### 类一：公开 / 非管理端点——字段名与字段值都不许出现

```text
// 样例 IP 用 RFC 5737 文档保留段（TEST-NET-2），是伪造样例，不是真实取证数据
posted = POST /公开读端点   // 落库时带 来源标识列 = 198.51.100.36（假值）
res = GET /公开读端点
assert "来源标识列" not in res.json()[0]        // 键不在
assert '"来源标识列"' not in res.body           // 整份响应文本里连字段名字符串都不出现
assert "198.51.100.36" not in res.body         // 连值都不出现在任意位置
assert res.json()[0].留言内容列 == "留言内容"     // 但业务数据照常可见（防误伤）
```

这里有一个**比常见做法稍强**的点，值得单独讲：

> 不止断言"键不存在"，还断言"值不出现在响应体任意位置"。

只看键的校验（如 JSON Schema 的 `additionalProperties: false`、字段白名单）能挡住"敏感字段以原名出现"，但挡不住敏感值**被改名、被拼进别的字符串字段、被嵌进别的结构**后流出。把整份 `res.body` 当纯文本、断言那串真实值不出现，覆盖面就宽一层。

——但这仍落在 Django `SimpleTestCase.assertNotContains`（断言某文本不出现在响应内容里）的语义之内，是既有一等公民的用法，不是新造的断言原语。本篇不夸口这一点，只是把它用在了"敏感值"上。

同时注意最后那行业务断言：**防泄露不能做成把该给用户的数据也一起藏了**。逆泄露断言必须成对写——"敏感的不出现"+"正常的仍在",否则会为了过测把功能砍掉。

### 类二：管理端列表——含 A 字段但不含 B 字段（正向对照）

管理端点确实要看到取证字段，所以它的断言是"**要含来源标识，但不含更敏感的那几样**"（例如密钥、会话版本、软删标记之类即便管理端列表也不该平铺）。这类断言是**对照**：证明"字段被裁掉"是因为构造上就不选，而不是因为测试环境没数据、断言恰好空真。

```text
row = (GET /管理端读端点)[0]
assert row.来源标识列 == "198.51.100.39"     // 管理端该看的看得到（正向对照）
// 注：secret_key 未真实出现，此处仅示意更敏感列不存在
```

没有类二的正向对照，类一的"全绿"可能是假绿灯：字段压根没进过这条路径，当然断不出泄露。两相对着，才证明"防的是真防住了、放的是确实放对"。

### 类三：端到端的"客户侧最小载荷"结构断言

针对下架态 / 隐身态这类"内容对客户不可见"的场景，端到端还有一层**结构断言**：处在这些态时，客户侧载荷只回极少几个字段（连状态位都不多给），从协议层面把暴露面压到最小。它守的不是"某个敏感列"，而是"整个响应的丰俭度"——能少给一个字段就少给一个。

## 一句话纪律

> 每加一个非管理端出口，就配一条"字段名 + 值都不出现（用 TEST-NET 假值）+ 业务字段仍在"的逆泄露断言，并配一条管理端正向对照防假绿灯。

这套"断言某文本不出现在响应里"的手法，公开早是框架一等公民（Django `assertNotContains`、Tavern 的默认严格 JSON 键匹配、Schemathesis 的 `response_schema_conformance`、JSON Schema `additionalProperties:false`），Discourse 的审核序列化器也已经是"白名单属性 + 按 scope 摘除邮箱原文 + 自由文本 payload 切片不平铺"。本案例是把这几样凑在一个小系统里、并额外用"值不出现在任意位置"补强键校验的盲区——补强有限，别当突破（第 05、07 段各说一次）。
