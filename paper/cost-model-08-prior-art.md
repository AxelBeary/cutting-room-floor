# 七、与公开先例的关系：哪些早被别人量过，哪些才是我们自己的

写到这里必须做一次诚实的清点。结论先给：**这套纪律里没有一条是"我们发现了别人不知道的规律"**，绝大部分核心事实早就被量化过、写进厂商文档了。真正属于我们的增量只有两处，7.4 会明确说清是哪两处——因为如果不说，读者会把第七节当成"我们独立发明了成本模型"，那正是这一节想避免的事。

## 7.1 主张一（往返是主因、成本关于轮次是二次的）：不新，而且已被量化

| 来源 | 说了什么 | 与本文的关系 |
| --- | --- | --- |
| 代理轮次控制研究（arXiv 2510.16786） | 真实编码任务上 token 成本随轮次**二次方增长**；中位轮次约 41–58；"管住轮次数量"是被低估的成本主因；仅设轮次上限省 24%–68%，动态预算再省 12%–24% | 这是本文公式的实证版本，比我们的 anecdote 硬得多 |
| 代理脚手架成本的一类工程分析 | 给出闭式三角数表达，并指出**缓存只压掉常数项，压不掉二次项** | 与 1.3 的判断一致 |
| 模型厂商官方文档 | 把代理系统成本描述为"上下文 × 轮次 × 并发"；明确每轮重传全部历史；多代理编排的 token 用量约为单代理的十倍量级（同一份文档给出的另一档是数倍量级） | 我们的口径本质是这条的重述 |
| 大规模工程实践复盘 | 总花费写成乘法式，往返次数是其中一项 | 佐证 |
| 真实代理负载的刻画性工作 | 用负载数据说明轮次数分布与上下文长度的耦合 | 佐证 |

**我们剩下的增量**：把这条从"知识"变成"评审禁令"——具体就是那两条：任何多代理方案的成本测算必须给出 N 的估计；**禁止只用 token/MB 体量做测算或承诺降幅**。这是一条流程约束，不是一条技术发现。

## 7.2 缓存修正这一层，反而更值得引官方口径

prompt caching 的倍率是公开信息，且比"打折"这个印象更细：命中前缀按基础输入价的 **0.1×**（个别新模型 **0.025×**）；写缓存 **1.25×**（5 分钟有效期）或 **2×**（1 小时有效期）；有存活时间与最小可缓存长度；这些倍率与批处理折扣**可叠加**。

这里有个我们一度搞反的细节，值得替读者省一步：**上面那篇轮次控制研究在实验设置里明确关掉了 prompt caching。** 所以它测到的二次方增长是一个**无缓存下界**——真实系统里常数项被缓存打折后，二次项的**占比只会更高**，也就是"往返优先"这个结论在带缓存的世界里更成立，而不是更不成立。这一点我们没在该论文里看到明确表述，属于我们能补的一句。

## 7.3 主张二（分段落盘 / 前置扫描 / 附页瘦身）：原理有先例，其中一条与主流相左

- **合并回合、少跑往返**：把多个动作合并进一次可执行回合以省步骤，是有公开量化结果的方向（如把动作表达为可执行代码、从而减少交互回合的工作，报告约省三成步骤）。各家代理实现指南里"minimize round trips"也是明确建议。
- **子代理只回摘要、产物写文件**：主流厂商文档直接这么推荐。我们的"明细落盘、只读汇总"是它的又一个实例。
- **确定性工作留在本地**：常见工程直觉，不需要我们先发现。
- **派工附页会随每轮重传**：这条其实就是 7.1 那个乘法式的直接推论，谁都能推出来；我们只是因为被烫过所以真的去瘦了页。

**唯一与主流相左的是"分段独立文件"。** 主流取向是对同一文件做定点编辑、或同文件分块追加，理由是 diff 连续可审、避免碎片化、对人类读者友好。我们明确选了另一头，并且承认它是**项目自选硬约束、不是业界共识**（第二节的适用边界就是给这条打的补丁）。这一点必须在发布稿里写显眼，否则很容易被读成"最佳实践推荐"。

## 7.4 主张三（主动用墙钟与本地算力换往返）：这才是本模型的辨识度所在，但要按"未检索到同类"来标

这是我们在公开材料里**找不到逐字同类**的一条。最接近的是两类：

- 把**文件系统当作代理的外部上下文**、主张"上下文中只留指针、产物落盘、压缩要可恢复"、甚至"失败的动作也要留在上下文里，因为删掉它模型就学不到东西"——这是架构直觉层面的近亲。
- 把**代理脚手架（harness）本身的开销量化**出来的一类讨论——它证明了"往返是有价格的、而且价格不小"。

但这些都没有把这句话立成一条**可以判定该不该做**的纪律，也就是第四节那套：明确许可清单（一次跑完全部闸门 / 双路互证 / 明细全量落盘 / 多跑一遍复算 / 慢而硬的检查值得跑）、一句判据（能在本地算出确定答案的事不值得占一次往返）、**三个失效前提**（本地算力真紧张 / 墙钟有硬 SLA / 多跑有副作用），以及**它与批处理折扣的正交性**（一个换单价、一个换趟数，可叠加、量纲不同）。

所以我们主张的强度只到这里：**"未见逐字同类"，不是"首创"。** 检索有边界，措辞不能越。

## 7.5 主张四（质量硬底线）：共识的部分是共识，少见的部分在配对

"别用质量换成本"没人反对，是共识。我们把三件具体的事写成**配对的、措辞是死的硬底线**——不得跳过已纳入的闸门、不得把 FAIL 静默降级为告警、不得丢弃明细——并且加上"报零命中前先自证能命中"，这一层在我们的检索里少见。

反方也要摆出来：有一类工作主张**按风险动态裁剪执行过程中的冗余检查/步骤**，公开报告 prompt 与 completion 同时降约两成、成功率还微升（另有对代理通信链做剪枝的同类结果）。它们没有推翻我们，因为它们裁剪的对象和我们保护的对象不是同一类——第五节 5.3 是正面回应，这里只做登记。

## 7.6 一句话立场

> 这一整套东西不是我们的发明，是**我们把别人已经量过的规律，用成了自己仓里的禁令**。属于我们的只有两处：把"本地算力换往返"写成可判定的纪律，和把质量底线写成三条不可打折的配对项。其余部分，你该去引的是上面那些来源，不是我们。
