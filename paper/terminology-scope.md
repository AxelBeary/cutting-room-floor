## 摘要（中）

多语本地化项目普遍把术语库存成"一个概念对应一枚必须使用的字符串"。我们在一个视觉小说项目群（七语至十语、单人委托 + 多代理施工）中发现：这种单词形锁定在特定概念上会**系统性失效**——不是因为某位译者水平不足，而是因为同一概念在西语、法语、巴西葡语三路互不通信的审校中**各自独立**收敛到"描述性短语而非单词"（附录 A 第 1 行）。这一现象**提示**"单枚词的语义宽度不足"可能是跨语现象而非单语缺陷；本稿把它作为**待验证假设**提出并按 §4.3、§7 的口径限定其强度，不主张印欧语共性已被证实。据此我们把锁定单元从"字符串"改为"带适用条件的词形集"，并提出按语义 scope 的三档判定框架：precise（逐词锁定，词形即叙事装置，不可归一）、lang_scoped（允许语内多枚合法形，锁集合与禁漂移）、global（世界观级，锁的是概念域与禁词清单，而非任何单一词形）；三档各自对应一种机器核对算子，使术语库从"风格建议"变成"可扫描的约束集"。配套的正向清点纪律（清点正确形在位，而不是反向扫描坏形）来自一次真实失效：把常用词登记成坏形、并以手抄字表跑批，单轮报出 **1479 条假警报**（附录 A 第 4 行）。本稿给出判定树、三档与扫描语义的映射、9 个判例（其中 6 个附可复算计数，见表 3），并明确写出局限：单项目群、N=1 团队、无"不分档"对照组、回证多数止于台账转录层。

**关键词**：术语治理；语义范围；多语本地化；视觉小说；LLM 代理；防回退扫描

## Abstract (EN)

Most translation term bases encode a term as "one concept → one mandatory string". Working on a visual-novel project group (7–10 languages, single client + multi-agent production), we found this lock fails systematically for certain concepts — not through translator error, but because three independent language reviews (Spanish, French, Brazilian Portuguese), with no cross-coordination, each converged on a *descriptive phrase rather than a single word* (Appendix A, row 1). This is evidence that insufficient lexical width **may** be a cross-language phenomenon rather than a single-language defect; we state it as a **hypothesis to be tested** and bound its strength in §4.3 and §7 — we do not claim an Indo-European commonality has been established. We therefore changed the locked unit from a string to a *conditional set of word forms*, and propose a three-tier semantic-scope framework: **precise** (form-level lock; the form itself carries a narrative device and must not be normalized), **lang_scoped** (several legitimate target-language forms; lock the set and forbid drift), **global** (world-view level; constrain the conceptual field and a banned-form list rather than any one form). Each tier maps to a distinct machine-checkable operator, turning the term base from style advice into a scannable constraint set. The companion discipline is *positive enumeration* — checking that locked correct forms are present, instead of black-list scanning for wrong ones — motivated by a real failure that produced **1,479 false alarms** in a single pass (Appendix A, row 4). We contribute the decision tree, the tier-to-operator mapping, nine cases (six with recomputable counts), and an explicit limitations section (single project group, N=1 team, no control condition, ledger-level verification for most figures).

**Keywords**: terminology governance; semantic scope; multi-language localization; visual novel; LLM agents; regression scanning

## 1. 问题：为什么"单词形锁定"会在某些概念上失效

### 1.1 观察起点

术语库（termbase / term db）在多语工程里的标准用法是"锁形"：一个概念在某语言登记一枚唯一正确词形，质检与扫描据此判定对错。这套做法在我们手上的项目里遇到三类反复失效，且失效模式互不相同：

1. **锁形过窄导致三路同时报缺**。源文本中一个英语侧已有窄义词（fishiness）的概念，西、法、巴葡三路母语代理各自独立得出同一结论：目标语没有一枚词能同时承载源文的"气味"与"语境"两个维度，必须用描述性短语。三路是互相不通信的独立通道（附录 A 第 1 行）。若按"锁形"口径，这会被读成三路代理都不合格；实际是单词可用性的问题。
2. **锁形过松导致世界观级误读**。法语里表达"野味腥膻"的现成词 fauve / bête / sauvage 单独看都合法，但在含非人类智慧角色的世界观文本里会被读者替文本补上源文没有的联想（把气味读成角色本身的体味，甚至引出更重的联想——该设定的具体内容本稿不展开），因此被整批禁用（附录 A 第 2 行）。这里没有任何一枚词形可以被"锁定"——正确约束是"这一类词都不许用"。
3. **锁形与真实用例打架**。韩语某称谓的库内锁定形与全书实际用例冲突（实况 25:8），终审裁定"错的是术语库不是译文"，回改库并全书归一（附录 A 第 3 行）。锁形一旦与语料实况对撞，锁本身需要被审。

三类失效不是同一病因，因此不能用同一种"锁"来处理。这是本稿的出发点。

### 1.2 研究问题与主张边界

- RQ1：能否用**一小组可判定问题**，把术语条目稳定分派到不同锁定强度，并使每一档都有对应的机器核对方式？
- RQ2：多路互不通信的目标语审校若在同一概念上得出同型结论，该结论的证据地位是什么（能否当作"语系共性"的证据而非"个别代理失误"）？
- RQ3：在 LLM 代理施工条件下，术语库怎样才不会被代理自己绕过或污染？

**明确不主张**：术语库作为单一事实源的价值、其 schema 与白名单生成器的工程实现（行业已是标准实践，且被既有底稿覆盖，见 §2.1 与附录 B）；本稿只主张跨语言语义 scope 分档这一层。

**划界（与同群两篇的分工）**：同批工作另有两篇——一篇主张**意图感知质检**（叙事装置伪装成错字时的四层防线与误杀/漏杀双向计量，下称"机关保全篇"），一篇主张**交付流程与闸门链**（母语子代理两轮审计、批次深挖、闸门收口的工业案例，下称"闭环篇"）。凡涉及"是不是机关"的判定次序与防线构造，唯一展开处在机关保全篇；凡涉及闸门链编制与子代理阵容，唯一展开处在闭环篇。**本稿只在"锁定单元与扫描算子是否匹配"这一层重述它们，重述处一律标注边界**（见 §3.3、§5.2、§6.2 与附录 B）。

### 2.3 学理锚点（待补正式综述）

"某语言用一枚词、另一语言只能用短语"是词汇空缺与词义宽度差异的经典现象；"锁概念域而非锁词形"在框架语义学里有自然表述。本稿不自建术语学理论，也不把这些框架当新引用主张：上述学理定位**未经本路查重核验**，投稿前须补正式文献综述并与术语学（terminography）主流文献对接，这是已登记的素材缺口（附录 A 第 5 行末段；参考文献 C 组）。

## 3. scope 分档框架

### 3.1 数据模型（最小形式）

一个术语条目按语言给出：

```
entry := { concept, status, forms: { lang -> (scope, W_lang, B_lang, φ) } }
  W_lang : 该语言合法词形集合      B_lang : 该语言禁词/禁形集合
  scope  ∈ { precise, lang_scoped, global }
  φ      : 适用条件（语域/说话人/章节/是否揭晓后/叙述 vs 对白）
```

三档的差别**只在 W 的基数与扫描算子**，不在人工严格程度：

**表 1｜三档语义与机器核对算子**

| 档 | 语义 | W 基数 | 锁的是什么 | 机器核对算子 | 不可机器核对的部分 |
|---|---|---|---|---|---|
| **precise** | 词形本身是叙事功能载体（叙事装置、双名、缩写梗、身份隐藏），改形即改设计 | 1（或成组指定互斥形） | "必须用这一枚，且不许被归一" | 等值匹配 + 旧形零残留 | "这是不是装置"需先判定 |
| **lang_scoped** | 该语存在多枚母语合法形，差异是语内风格而非对错 | ≥2 | "集合内可用；集合外新形即漂移" | 集合成员检查（命中 W 即通过，W 外报警） | 集合边界是否合理需语料佐证 |
| **global** | 冲突发生在概念域/世界观层，任何单语现成词都可能引入源文没有的联想 | 可为 0（纯禁令） | "这类词都不许用"／"跨语统一走音译" | 禁词表 B 命中扫描 + 概念级母语核对 | 世界观误读必须靠母语判断与考证 |

三档共同遵守一条：**档由概念的语义性质决定，不由语言决定**。同一语言里三类条目并存是常态。

### 3.2 判定树（从判例归纳，节点均可回证）

```
闸0  这串文字真的渲染给玩家吗？
     └─ 否（引擎比较键 / 分派键 / 内部技术名）→ 不入术语库
        依据：改动前须读引擎源码定性该串是否渲染，改非渲染串＝零玩家收益＋有功能风险〔附录 A 第 6 行〕；
        用户可见改名要与内部技术名严格分层，同名先做撞车检查〔附录 A 第 7 行〕
闸1  词形本身是否携带叙事功能（双形装置 / 伏笔 / 口误笑话 / 身份隐藏）？
     ├─ 是 → 【precise】：逐词锁定，跨语禁归一，
     │        且必须把该形自动写进派工白名单（否则被下游当错字上报）
     │        依据：拼写变体先问"是不是装置"再谈"是不是错字"，一对双形装置（本稿称机关甲、机关乙）
     │              各计 45 处与 127 处，集中于特定路线的章节，曾被前序会话误判"统一"〔附录 A 第 8 行〕；
     │              "曾把有意设计的拼写装置当错字统一，属重大事故"〔附录 A 第 9 行〕；
     │              "白名单没进派工契约——这是最狠的一条"〔附录 A 第 10 行〕
     └─ 否 → 闸2
闸2  目标语现成词是否会把源文没有的世界观/语用联想读进来？
     ├─ 是 → 【global】：以概念域下禁令（禁词表），跨语口径统一，
     │        必要时锁音译而非锁译名
     │        依据：fauve/bête/sauvage 在含非人类角色的世界观文本里引出源文没有的联想→全部禁用〔附录 A 第 2 行〕；
     │              巴葡 presente de primeiro encontro 首读"（恋爱）第一次约会"→雷点词登记〔附录 A 第 11 行〕；
     │              陌生方物只有音译能让各语读者站在同一视角，禁各语俗名〔附录 A 第 12 行〕
     └─ 否 → 闸3
闸3  该语是否有多枚母语合法形（含全书用例分布支持）？
     ├─ 是 → 【lang_scoped】：登集合 W + φ（叙述/对白/亲称尊称分开），
     │        明写"不得以多语不一致为由要求归一"
     │        依据：法语登三个合法词形、旧单一锁定形 goût de marée 作废〔附录 A 第 13 行〕；
     │              库内锁定形与实况 25:8 冲突时回改库〔附录 A 第 3 行〕；
     │              跨语口径类判据（例如"是否补计量单位"取决于有没有合计类锚点词）须写进库本身，防下一轮拉锯〔附录 A 第 14 行〕
     └─ 否 → 兜底【precise】
```

判定树有两处"降级出口"值得单列，它们是分档框架自身的稳定性设计：

- **变体先定域**：葡语/西语这类多变体语言，必须先拍死单一变体（如 pt_BR）再谈词形集，否则 lang_scoped 的 W 会变成跨变体的任意形堆；口径写进子代理身份、禁用"中性××语"表述（附录 A 第 15 行）。
- **亲译基准优先**：作者亲译本在场时，它是**基准**而非可被"统一"的对象，语言侧审校代理对其只作助手不作裁判；scope 判定与亲译本冲突时，先复核判定，不先改译文（附录 A 第 16 行）。

### 3.3 分档的实际收益：把"可核对性"变成一等公民

分档前，"术语检查"只有一种算子（等值），因此只有 precise 条目可被机器核对，另两类要么假阳性、要么静默漏。分档后：precise 走零残留、lang_scoped 走集合成员 + 新形报警、global 走禁词表 + 概念级人工核对，每一档都清楚自己**能被机器证明什么、不能证明什么**（表 1 最后一列）。这是本稿认为比"建库"更值得写的部分：术语库的效力上限取决于锁定单元与扫描算子是否匹配。

> **划界**：闸 1 分支背后的四层防线构造（单一事实源、锁定形与禁形的双语义分层、豁免名单自动生成进派工契约、人工拍板闸）以及"误杀装置 / 漏杀缺陷"的双向误差计量，在机关保全篇完整展开；本节只取其中与分档耦合的一环——**档决定算子**。

## 4. 三语独立收敛证据

### 4.1 证据陈述

同一概念（源文侧带窄义词 fishiness 的气味类表述）由西语、法语、巴西葡语三路母语审校**各自独立**通读得出同一型结论：**目标语须用"描述性短语而非单词"**。留档原话："西/法/葡三语各自独立收敛到『描述性短语而非单词』……这说明英语 fishiness 的窄义不是英语独有的缺陷，是印欧语的共性"（附录 A 第 1 行、第 17 行）。注意：引文末句是**当时的解释性表述**，其证据地位由本稿重新界定，见 §4.3。

据此落地的治理动作不是"再翻一遍"，而是改数据模型：由严格字符串锁定改为**带适用条件的 scope 制词形集**——法语登记三枚合法词形，旧的单一锁定形 goût de marée 作废（附录 A 第 13 行）。

### 4.2 为什么"独立收敛"在本案例里有较强证据地位

1. **通道独立**：三路母语代理按语言分派、各读全篇，结论生成时互相不可见（附录 A 第 18 行：第一轮七个母语子代理各通读全篇，每语正文 8400+ 行，另含全部界面文件）。
2. **反证被主动排除**：若结论是代理能力问题，应表现为三路结论分歧；实际是同型收敛，且分歧点落在**各语内部的实现细节**（短语怎么搭）而非"要不要短语"。
3. **同型现象在同批数据里二次出现**：正式开译前的母语"探路轮"中，西、法、巴葡三路又各自独立发现同一处节拍漏洞——源文一处依赖方言词面理解的小桥段，若只意译词义会丢两拍（该方言词属锁定形，本稿不给出词形；附录 A 第 19 行）。两案叠加，"多语独立通道得出同型结论"在本项目里至少出现 2 组 × 3 路，而非孤例。
4. **对照：不独立时的假收敛**：外部/AI 审校报告的意见未经独立通道即被采纳，会引入源文没有的第三种写法（俄语选项句被建议追加一个常用小品词，而其余六语已按"选项＝台词前半逐字相同"对齐，加上该词即成三形并存）（附录 A 第 20 行）——说明"同型结论"必须来自独立通道才有证据地位。

### 4.3 结论的强度与被否证的读法

本稿只主张：**在该项目群、该概念集上，"必须短语化"不是单语缺陷**，因此术语库不能把锁定单元默认设为单词形。它**不**主张"印欧语共性"已被语言学证实——那是留档当时的解释性表述，样本是 3 路同项目代理而非独立研究者复现（见 §7 局限 L3、L4）。措辞上把该解释降级为**待验证假设**，是本稿的自我约束；摘要与正文按同一口径书写。

## 5. 防回退：正向清点为何优于反向黑名单

### 5.1 反向黑名单的三种实测失效

**表 2｜反向黑名单的三种失效模式与测量条件**

| 失效模式 | 症状 | 测量条件（口径见附录 A 对应行） | 出处 |
|---|---|---|---|
| **常用词登记成坏形 → 假阳性爆炸** | "把'老鼠'登记成坏形，结果詈语、明喻、'内鬼'俗语四处全中"；同批另一手段（为查源语残留手抄一张 369 字表跑批）单轮报出 **1479 条假警报**，最终改走免字表法 | 单轮跑批、整库译文；两条引文出自同一会话记录的不同段落，不并列成同一次测量 | 附录 A 第 4 行 |
| **只登记单语形 → 结构性漏防** | 错字档只登记了俄文形（ящерица），法/葡的小写形没进去，"所以扫描永远拦不住" | 单一术语条目、三语比对 | 附录 A 第 21 行 |
| **判据与被验值同源 → 假绿** | 断言的"期望值"凭记忆写，与被验的错值同源而通过；自检报告写"全部修对、零残留"，实际把原本正确的 15 处拼写全改成了错的 | 一轮批量替换的自检报告 ↔ 磁盘回读 | 附录 A 第 22 行 |

第三种最隐蔽，因为它不是漏报，而是**扫描器与被扫描内容一起被同一个错误污染**。

### 5.2 正向清点五步（项目内现行口径）

1. **清点 locked 正确形在不在位**，取代反向扫黑形："比'反向扫黑形'准得多"（附录 A 第 4 行）。
2. **白名单永不手写**，由术语库现跑现出（生成器实跑产白），避免手抄污染与陈旧副本（附录 A 第 23 行）。
3. **同步链强制**：改库 → 重生成白名单 → 对齐扫描，三步缺一即成"三重保护缺口"（旧词形残留在派生白名单里的实例）；拍板词形只记留档不当场入库，则词表/防回退/巡检白名单三重保护同时漏（附录 A 第 24、25 行）。这条链的量级可以用一个风险推演说明：若直接沿用共享工具的默认档案跑一次批，其覆盖范围足以把 420 行已定稿句改回旧写法——**这是风险量级而非已发生的事故**，本稿按此定性引用（附录 A 第 44 行）。
4. **扫描器按语言路由并排除注释/old 行**；拆字演出（一字一顿、被打断的拟声）会被词边界正则误切，须显式登记进白名单，否则每轮重现假阳性（附录 A 第 26 行）。
5. **零命中前先自证能命中**：任何"零命中/全绿"结论之前，必须先证明扫描器在该模式下确实能命中——做法是植入已知阳性样本或用书中满处都是的本土标记做自检（如以 vale / venga / vosotros 验证变体扫描有效性，排除"全零是因为正则没生效"的假阴性）（附录 A 第 27 行）。

工具前提还有一条与语言直接相关：手写 CJK 字符串匹配会**静默漏命中**（同一词 grep=0 实为已存在于该行），计数与校验一律走能命中目标文字的工具链（附录 A 第 28 行）。正向清点若跑在假阴性的检索上，等价于没做。

> **划界**：本节五步只保留到"为什么正向清点必须依赖分档"这一层。作为可被人照着执行的规程（生成器参数、闸门调用序、派工契约模板、豁免登记格式），它属方法论手册辖域，工程实现本体另成一篇（附录 B）；闸门链在交付侧的位置与其余六道闸门，唯一展开处在闭环篇。

### 5.3 scope 分档与防回退的耦合

三档对第 1 步的含义不同，这也解释了为什么"不分档的防回退"必然失败：precise 清点"唯一形在位且旧形零残留"；lang_scoped 清点"命中集合内任一形"，其**残留判定必须以集合为基**，否则把合法变体当回退对象；global 清点的是"禁词表零命中 + 概念级读法仍成立"，前者机器可核、后者必须回到母语判断与实物/语料考证（附录 A 第 12 行：多源实物考证后拍板；第 29 行：真人母语反馈可正当重开已锁定的机器决策）。

## 7. 局限

- **L1 单项目群、N=1 团队**。全部证据来自同一委托人与同一代理群下的若干项目（视觉小说多语本地化及其工具链）；无跨团队、跨组织复现。这是本稿新颖性与可信度的共同上界。
- **L2 回证深度**。本批留档已收回维护者仓库内，可逐级下钻（拆解摘要 → 台账 → 主题索引 → 原始会话摘录 → 复算脚本）；但**本稿多数主张仍止于"索引 ↔ 台账"两级**，凡本轮已下钻到会话摘录层的行，附录 A 逐行标明取证层级。故"坐实"意为**留档忠实转录**，不等于底层事实已被独立复现。
- **L3 独立性的强度**。§4 的三路"独立"指会话通道独立与派工分域独立，**不等于**彼此无共享：三路提示词是否含共同口径，留档未记录，无法排除共因（如同一事实源文档注入同一先验）。这是该证据最实质的威胁。
- **L4 概念集非随机抽样**。触发"必须短语化"的概念是项目中被反复审校的少数条目，不能据此估计数码占比，也不能反向主张"多数术语需要分档"。分档框架对既有库的覆盖率属未测项。
- **L5 无对照组**。没有"不分档会怎样"的反事实测量：1479 条假警报属另一失效模式（反向黑名单），不是分档缺失的直接代价；因此本稿不写任何"提升了多少质量"的效果声明。
- **L6 三档命名为本稿归纳，且其来源需限定**。"scope 制词形集"是留档原话；precise / lang_scoped / global 三个档名借自同一批挖掘留档中**另一个治理域**（字体资源收窄的逐目标三档分级）的既有标签，本稿重新赋义于术语域。两点限定必须写明：其一，本框架的可辩性建立在**判定树与算子映射**上，不建立在名的来源上——换一个标签集不动结论；其二，主题索引里有三行是因 `scope` 一词撞词被误收的离题条目（其内容属前述另一治理域），交叉验证已判为噪声，本稿不把它们当术语治理证据引用（附录 A 第 45 行）。撞词本身只作一个观察：scope 词汇在"证据范围与优化范围必须对齐"的两个不同治理域各自出现，属巧合而非本稿证据。
- **L7 语言类型学覆盖**。主证据在罗曼语 + 斯拉夫语 + 东亚非拉丁文字（谚文/泰文/日文），缺形态学上更远的语言（如黏着语、屈折更重的语言）验证。
- **L8 术语学的学理定位未做综述**（§2.3）。投稿前须与术语学/词义空缺文献正式对接，否则易被判为"工程随笔"。
- **L9 匿名化与可复核性的张力（本轮新增）**。为避免暴露未发布内容，本稿对装置型词形、各语派生音译形、具体台词与章节位置做了代号化或构造例替换（表 3 内两处标"构造例（不取真值）"）。**凡被替换处，其真值仍在维护者留档内可复核**，但读者无法从公开稿自行验证——这是发表形态的固有代价，构造例只演示机制、不承担证据职能。

## 8. 结论

本稿的可迁移主张是三件事，且都不是"建库"本身：

1. **锁定单元应是"带适用条件的词形集"，默认单词形是错的**。三路独立收敛到"描述性短语而非单词"给出的是失效的直接证据：单词语义宽度不足若跨语言出现，就不能归因于单语或单个代理（其跨语共性的强度按 §4.3 作待验证假设读）。
2. **按语义 scope 分三档，档与机器核对算子一一对应**（precise→等值 + 旧形零残留；lang_scoped→集合成员 + 新形报警；global→禁词表 + 概念级母语核对）。分档的实际作用是**划清每一项约束能被机器证明到哪一步**，剩下的明确交回母语判断与考证。
3. **防回退必须走正向清点，并对每个计数标口径**：清点 locked 正确形在位，白名单由库派生且与库同步，零命中前先自证能命中，任何"缺 N 语"结论须先排除数据写法导致的假缺口。

结论强度受 §7 约束：单项目群、通道独立性无法完全证明、无对照组。下一步最有价值的两项补验是：把三路判定拆到**彼此不共享事实源文档**的条件下复跑（正面回应 L3），以及在**另一个团队的项目**上按本判定树分档，测"多少既有库条目需要从 precise 改档"（回应 L1、L4）。

**投稿定位**：翻译技术 / 术语管理方向的短文（研究性工程论文），与闭环论文（多语质量交付流程）、机关保全论文（叙事装置的意图感知质检）互补不重叠；三篇分主张"约束分档—流程与闸门—意图感知"三个不同层面，判例只在 owning 篇展开、他篇仅指向（附录 B）。
